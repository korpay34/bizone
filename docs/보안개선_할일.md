# 보안 개선 할 일

챗봇 연동 작업(feature/chatbot) 중 확인한 항목입니다. 이번 작업에서는 고치지 않았고, 별도 작업으로 진행합니다.
실제 값은 이 문서에 적지 않습니다. 위치는 줄 번호 대신 함수·파일 이름으로 적었습니다(2026-10-22 기준).

## 1. SESSION_SECRET 하드코딩 기본값

- 위치: `worker/index.js` — `createInquiry()`, `inquiryDetail()` 의 `env.SESSION_SECRET||"…"`
- 문제: Worker 비밀값이 빠지면 소스에 공개된 고정 문자열이 Q&A 비밀글 비밀번호 해시의 salt 로 쓰인다.
  관리자 로그인(`adminLogin`)은 비밀값이 없으면 503 으로 막지만, Q&A 쪽은 조용히 기본값으로 동작한다.
- 할 일
  - 기본값을 없애고, 비밀값이 없으면 문의 등록·조회를 503 으로 막는다(관리자 로그인과 같은 방식).
  - 기본값을 지운 뒤에는 이미 기본값으로 저장된 글이 있는지 확인한다. 있으면 그 글은 비밀번호가 맞지 않게 되므로
    전환 방법(한시적으로 두 방식 모두 확인 → 확인 시 새 해시로 갱신)을 정한다.

## 2. FormSubmit 수신 이메일 노출

- 위치: `static-src/inquiry.js`, `static-src/navigation.js`, `static-src/support-consultation.js` 의 `fetch('https://formsubmit.co/ajax/…')`
- 문제: 직원 개인 메일 주소가 모든 방문자 브라우저에 그대로 내려간다. 스팸 수집 대상이 되고,
  누구나 같은 주소로 임의 메일을 보낼 수 있다. 담당자가 바뀌면 JS 3곳을 고쳐야 한다.
- 할 일
  - 상담신청을 Worker API(예: `POST /api/consultations`)로 받고, Worker 가 메일을 보내거나 D1 에 저장한다.
    수신 주소는 Worker 비밀값으로 옮긴다.
  - 최소 조치로는 FormSubmit 의 랜덤 별칭 주소를 쓰고, 수신 주소는 개인 메일 대신 팀 공용 메일로 바꾼다.
  - Worker 로 옮기면 `html()` 의 CSP 에서 `https://formsubmit.co` 허용도 뺄 수 있다.

## 3. Q&A 비밀번호 해시

- 위치: `worker/index.js` — `createInquiry()`, `inquiryDetail()` 의 `sha256Hex(\`${password}:${SESSION_SECRET}\`)`
- 문제: 4자리 이상 비밀번호를 SHA-256 한 번으로 저장한다. 글마다 다른 salt 가 없고 계산이 빨라서,
  DB 가 유출되면 짧은 비밀번호는 금방 맞춰진다. 비밀번호 확인 시도 횟수 제한도 없다.
- 할 일
  - PBKDF2(Web Crypto `deriveBits`, 글마다 무작위 salt, 반복 횟수 저장)로 바꾼다. 기존 글은 확인에 성공할 때 새 방식으로 갱신한다.
  - 글·IP 기준 비밀번호 확인 실패 횟수 제한을 둔다(관리자 로그인의 `admin_login_attempts` 와 같은 방식).
  - 비밀번호 최소 길이를 4자리보다 늘리는 것을 검토한다.
